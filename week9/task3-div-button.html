WEEK 09 / TASK 03

Div Button.

Replace clickable non-semantic elements with real buttons that support keyboard and assistive technology.

← Back to all Week 9 tasks

The problem

A div is a generic container. Adding an onclick handler does not automatically give it button semantics, keyboard behavior or focusability.

Incorrect pattern
<div onclick="saveBudget()">
  Save budget
</div>

This is not naturally keyboard-focusable and is not announced as a button.

Correct pattern
<button type="button"
  onclick="saveBudget()">
  Save budget
</button>

Native buttons support keyboard activation and expose the correct role.

Keyboard test

Use Tab to move to the button, then press Enter or Space. The status below should update.

Not saved yet.

When a custom control is unavoidable

Prefer native HTML. If a custom widget is genuinely required, it must provide an appropriate role, tabindex, accessible name, keyboard handling and state. A custom button typically needs both Enter and Space activation.

<div role="button" tabindex="0"
  aria-label="Save budget"
  onkeydown="if(event.key==='Enter'||event.key===' '){event.preventDefault();saveBudget()}">
  Save budget
</div>
This custom example is for learning only. Use a real <button> whenever possible.
