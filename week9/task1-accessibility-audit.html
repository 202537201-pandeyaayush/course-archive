Accessibility Audit Report.

A structured accessibility review of a sample Student Budget Tracker interface.

Executive summary

This report reviews a representative Student Budget Tracker interface used by Team 4. The goal is to identify barriers for keyboard users, screen-reader users and people with low vision, then document fixes and retesting.

4Example findings before fixes
4Fixes demonstrated and retested
HighPriority: keyboard and form access
WCAG 2.2Reference standard for review
Measurement note: This is a documented classroom example, not a real Lighthouse scan. Run Lighthouse on your deployed project and replace any example scores or findings with your actual results before submitting.

Scope and method

Pages/components reviewed: dashboard navigation, Add Expense form, Save Budget action, category chart and summary cards. Method: visual inspection, keyboard-only navigation, checking accessible names and reviewing color contrast. Automated tools can help, but they do not replace manual testing.

Findings and recommended fixes

IssueUser impactRecommended fixPriority
Icon-only action has no accessible nameScreen readers announce an unclear controlAdd a visible label or descriptive aria-labelHigh
Form input relies on placeholder textLabel may disappear while typingAssociate a persistent label using for/idHigh
Keyboard focus is difficult to seeKeyboard users can lose their positionAdd a strong :focus-visible outlineHigh
Muted text has weak contrastText is difficult to readUse a tested foreground/background pairMedium

Retest checklist

  • Tab through every control and confirm visible focus.
  • Activate buttons with Enter and Space.
  • Confirm each input has a persistent label.
  • Check text contrast with a contrast checker.
  • Run Lighthouse and record the actual date, URL and score.
