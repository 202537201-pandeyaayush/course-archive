1. Why script loading matters

A normal script in the document head can pause HTML parsing while it downloads and runs. The defer attribute downloads the script in parallel and executes it after parsing is complete, preserving the order of deferred scripts. The async attribute also downloads in parallel, but executes as soon as it is ready; execution order is not guaranteed.

3. Code comparison

Parser-blocking script

<script src="app.js"></script>

When placed in the head without async or defer, the browser pauses parsing to fetch and execute it.

Deferred script

<script src="app.js" defer></script>

The script downloads while HTML parsing continues and runs after the document has been parsed.

Async script

<script src="analytics-demo.js" async></script>

The script runs as soon as it is ready. Use async for independent scripts that do not rely on execution order.

4. Recommended approach for this project

Use defer for main interface scripts that need the page elements to exist and should execute in document order. Use async only for independent scripts where execution order does not matter. Avoid adding analytics or third-party scripts unless they are actually required.

5. Conclusion

Deferred loading keeps the HTML parser moving while a script downloads and provides predictable execution after parsing. Async loading is useful for independent scripts, but its execution order is not guaranteed. Choosing the correct loading strategy helps avoid unnecessary delays.
